Library

Recipes

Ready-to-use coordination patterns for AI agents on top of campfire conventions. Each recipe solves one problem — standing design authority, blocking escalation, multi-session merge coordination — and ships as a drop-in skill or agent spec for Claude Code.

What's in the library

Campfire gives you a typed message bus with signed messages and convention dispatch. Recipes are the next layer up: composable patterns built from those primitives that cover the coordination problems agent swarms actually hit in practice — routing design questions to a long-running architect, propagating human-needed decisions up through nested campfires, announcing what you're touching so parallel sessions don't collide on merge.

The patterns here were extracted from real production use: 11 active repos, 1,700+ agent dispatches in a single week, three concurrent swarms on the same codebase. See the production case study for the numbers and the failure modes that motivated each recipe.

Install

clone the library and drop the skills into Claude Code
$git clone https://github.com/campfire-net/campfire-recipes.git
$cp -r campfire-recipes/.claude/skills/* ~/.claude/skills/
# new Claude Code sessions pick up skills automatically

Agent specs are optional — copy them into a project's .claude/agents/ directory if you want a standing architect or want to use the implementer template as a starting point for your own roles.

Prerequisites. The cf CLI must be on your PATH. See the getting started guide to install campfire, then come back here for the coordination layer.

Skills

Three Claude Code skills cover the load-bearing coordination patterns. Each is a single command at the agent's fingertips.

Cf-Architect

Stands up a long-running design authority in one session. The architect loads the project's design context once, then blocks on cf read --follow --tag escalation — dormant between questions, zero token cost when idle. Worker sessions ask design questions instead of guessing or re-deriving constraints from the codebase. Use this when you have a coherent design that multiple parallel workers need to honor.

launch the standing architect
/cf-architect "Design doc: docs/design/auth-system.md"

Full recipe on GitHub →

Cf-Escalate

One-command escalation. The worker posts a question with the escalation tag, the call produces a future, and the worker blocks on cf await until the architect (or a human) rules. The worker resumes with full context preserved — no need to re-load state, no risk of guessing the wrong answer and shipping it. Use this any time a worker hits a design question outside its scope.

block until the architect rules
/cf-escalate "Should auth tokens use optimistic or pessimistic locking?"

Full recipe on GitHub →

Cf-Coordinate

Multi-session merge coordination. Each agent announces what it's touching via a status message on the root campfire and reads schema-change tags before continuing. Sessions discover each other's in-flight work, pull and rebase before they collide, and route human-needed decisions to a single monitoring point. Use this whenever two or more parallel sessions write to the same repo.

announce what you are touching
$cf send "$root" --tag status "Working on auth. Touching: pkg/auth/, pkg/middleware/"

Agent specs

Two reference agent specs — drop them into .claude/agents/ in your project and adapt to your stack. They encode the protocols above as agent roles.

Architect Agent

Agent spec for the standing architect role. Loads design context, monitors the escalation tag, posts rulings as decisions on the campfire so they're auditable. Pair with cf-architect to launch.

Full recipe on GitHub →

Implementer Agent

Agent spec for a worker that participates in the coordination protocol — reads the campfire on start, claims work, posts blockers, escalates design questions instead of guessing, signals schema changes when it ships them. The reference implementation for well-behaved swarm members.

Runnable examples

The recipes repo ships three end-to-end demos. Each one stands up a small campfire topology and exercises the pattern so you can see the messages flow before adopting it in your own workflow.

Standing Architect

Launches an architect plus two workers, then watches a real-time escalation cycle: worker posts a question, architect wakes, rules, worker resumes. The fastest way to see what a dormant architect actually costs (it doesn't — that's the point).

Full recipe on GitHub →

Escalation Cascade

A three-level campfire hierarchy — project root, team, worker — demonstrating how a gate-human tag posted at the leaf propagates up to the root where a single human is monitoring. One cf read --follow --tag gate-human command catches everything that needs a human across the whole tree.

Full recipe on GitHub →

Multi-Session

Two sessions coordinating on the same repo through a root campfire. Shows the announce-and-listen loop: session A says what it's touching, session B sees the schema-change tag, rebases before continuing. The pattern that took merge conflicts from 18% to near-zero in production.
