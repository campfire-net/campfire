## What Changed

cf 0.30 is a structural release. The primary goals were:

1. **Reorganize the substrate into a layered module system** — separating the
   wire protocol (`cf-protocol`) from the convention machinery and L3 convention
   implementations (`cf-conventions`).
2. **Ship a complete trust authority** — `cf-authority` provides a full
   delegation-chain evaluator with a declarative gate predicate language.
3. **Freeze the wire format** — a CI-enforced reflection verifier prevents
   accidental wire-incompatible changes from reaching `main`.
4. **Fix a critical trust-anchor bypass** — `GrantPayload` CBOR field 5
   (`GranterPubKey`) closes a chain-root verification gap.

The SDK-level API (`protocol.Init`, `client.Send`, `client.Read`, etc.) is
unchanged. Most consumers need only a `go.mod` bump; see the
[upgrade guide](upgrade-0.19-to-0.30.md) for the full decision tree.

---

## Why

Before 0.30, campfire had a single flat `pkg/` directory. All substrate types,
convention machinery, and higher-level convention implementations lived side by
side. This created two problems:

**Coupling.** There was no enforced boundary between the wire-protocol layer
(CBOR types, transport, store) and the convention layer (dispatch, gate
evaluation, trust chains). Any package could import any other. The L2 dispatcher
could (and sometimes did) import L3 implementations, creating import cycles.

**Trust gaps.** The `GateEvaluator` interface existed but had no production
implementation wired into the dispatcher. The `AllowAllGateEvaluator` stub was
the default everywhere — meaning convention operations were not gate-evaluated
in practice. The shared-key session model (`cfs1_` tokens) destroyed per-worker
attribution. The TOFU pin HMAC used only the first 32 seed bytes rather than
a proper sign-fixed-input derivation.

0.30 closes both gaps: enforced depguard rules at CI prevent layer violations,
and `DefaultGateEvaluator` is wired into `ConventionDispatcher` so every
operation is evaluated.

## Architecture

cf 0.30 is organized into four layers.

### L1 — Substrate (`cf-protocol/`)

The substrate layer owns the wire format and transport. It is the only layer
that knows about CBOR field IDs, transport types, and store internals.

```
cf-protocol/
  internal/          ← All substrate implementation (not importable from outside)
    campfire/
    message/
    store/
    transport/fs/
    transport/http/
    tagspec/
    reserved-ops/
    ...
  protocol/          ← Public re-export surface (type aliases only)
```

The public surface (`cf-protocol/protocol`) re-exports all client-facing types
as type aliases — `Client`, `Message`, `MemberRecord`, all request/result
types, and the constructors `Init`, `InitWithConfig`, `New`. Callers importing
`pkg/protocol` (the forwarding shim) compile unchanged.

**Wire-format freeze.** `wireverify_test.go` uses real reflection to assert CBOR
field IDs, mandatory fields, and enum values for every L1 type. Any accidental
change to the wire format fails CI before merge.

**`cf-primitives` binary.** A separate binary exposing exactly the 12 frozen
protocol commands (`admit`, `await`, `create`, `disband`, `evict`, `init`,
`join`, `leave`, `members`, `read`, `send`, `subscribe`). A ceiling test
(`TestPrimitivesSurfaceCeiling`) enforces the count — additions require
adversary review.

### L2 — Convention Machinery (`cf-conventions/cf-convention/`)

The convention layer declares the interfaces that L3 packages implement. It
imports L1 (`cf-protocol/protocol`) but must not import any L3 package — the
`depguard_test.go` in the package enforces this at CI.

Key L2 artifacts frozen at cf-conventions 1.0:

| Symbol | What it is |
|--------|-----------|
| `GateEvaluator` | Interface for delegation gate evaluation |
| `ProvenanceCheckerV2` | Interface for sender provenance checking |
| `IdentityResolver` | Interface for resolving sender identity |
| `ConventionDispatcher` | Core dispatch loop — calls `GateEvaluator.Evaluate` before every operation |
| `DefaultDeniedTagPrefixes` | Denylist: `campfire:`, `session:`, `naming:` are reserved |
| `Server` | Convention server SDK |
| `Executor` | Client-side convention executor |

The `DefaultDeniedTagPrefixes` denylist blocks convention declarations from
using reserved L1 system event tag prefixes. No L3 convention can override
the reserved-op floor — it is enforced at the L2 dispatcher boundary (D5).

### L3 — Convention Implementations (`cf-conventions/<pkg>/`)

Seven L3 packages implement the L2 interfaces for specific domains. They import
L2 (`cf-conventions/cf-convention`) and L1 (`cf-protocol/protocol`) but must
not import each other horizontally. The depguard rules enforce this.

| Package | Domain |
|---------|--------|
| `cf-authority` | Trust chain evaluation, grant management, gate predicates |
| `cf-identity` | Identity ceremonies (introduce, declare-home, verify) |
| `cf-session` | Session lifecycle, lazy-mint per-worker grants |
| `cf-discovery` | Namespace discovery, beacon signing, 3-tier resolver |
| `cf-durability` | Message lifecycle and TTL tag semantics |
| `cf-connect` | Social connection protocol (connect-request/accept/reject) |
| `cf-convention-extension` | Convention promote and supersede operations |

See [`cf-conventions/README.md`](../cf-conventions/README.md) for a tour of
each package and `cf-conventions/<pkg>/README.md` for per-package docs.

### L4 — Surface (`cmd/cf`, `cf-mcp`, `cf-functions`)

The surface layer is the user-facing CLI and hosted service. It imports L3
packages but has no protocol knowledge of its own — it delegates to the
`protocol.Client` and `convention.Executor`/`Server` APIs.

**argv[0] dispatch.** The `cf` binary detects symlink invocation (e.g.
`dontguess → cf`) and loads `~/.cf/apps/<name>/config.toml` as a per-app
config overlay. Each symlinked app gets its own identity, transport defaults,
and naming seeds.

**Protocol-primitive commands hidden.** `cf --help` shows only convention
operations. Protocol primitives (`send`, `read`, `await`, etc.) are accessible
via `cf --help-primitives` or the `cf-primitives` binary (frozen surface).

**MCP tool generation.** `cf-mcp` generates MCP tools directly from convention
declarations. `DefaultGateEvaluator` is active in all modes (dev, test, hosted).

## Session Model (New in 0.30)

The old `cfs1_` session token embedded a shared private key, giving all workers
the same identity. This destroyed per-worker attribution and broke audit trails.

0.30 replaces it with a **lazy-mint** model:

1. Orchestrator creates a session campfire using its own identity key.
2. Orchestrator emits `session:open` with a `CapabilityTemplate` (convention,
   op glob, TTL).
3. Each worker generates a fresh Ed25519 keypair and requests a grant.
4. Orchestrator issues a per-worker grant (`IssueWorkerGrant`) scoped to
   `parent_grant ∩ template`. Each worker has a unique, attributable identity.
5. Orchestrator closes the session with `session:close`; the coordination log
   is eligible for compaction.

`cfs2_` tokens embed real transport config, not a private key. `cfs1_` tokens
return a clear migration error.

## Trust Authority (New in 0.30)

`cf-authority` (`DefaultGateEvaluator`) implements the full five-leaf gate
predicate language:

| Predicate | Description |
|-----------|-------------|
| `level: N` | Minimum provenance level |
| `grant: <conv>:<op>` | Exact capability required |
| `grant_in: <conv>:<op-glob> at <where>` | Scoped capability |
| `grant_quota: <axis> >= <bound>` | Quota bound |
| `chain_to: <pubkey>` | Trust anchor by key |
| `chain_to_quorum: M-of-N` | Multi-sysop authority |
| `all_of: [...]` | AND composition |
| `any_of: [...]` | OR composition |

Maximum AST nesting depth: 3. No `not:` predicate (use `OwnerPolicy.BlanketDeny`
for denial).

All 10 D-class deal-breakers are implemented: chain walk, revocation,
scope ceiling, reserved-op floor, depth limit, owner ceiling, and TTL
enforcement. A separate wire-format freeze verifier in `cf-authority/` runs
15 mutation-confirmed tests on every PR.

## Discovery (New in 0.30)

Center-finding (automatic locality at `Init` time via `walkUpForCenter`) is
removed from the substrate. Locality now resolves at the discovery layer
(`cf-discovery`, L3).

The 3-tier model:

| Tier | What happens |
|------|-------------|
| Tier 1 | Validate and sign a snippet (name, description, member count bucket, freshness window, parent signature) |
| Tier 2 | Name resolution with TOFU pinning — `Resolve("baron.dontguess")` |
| Tier 3 | Full join + post-join probe-write-then-observe verification |

`ResolveChain` walks multi-level chains (e.g. `rd.ready.3dl`) with per-hop
snippet verification. Freshness composition uses the **minimum** window across
hops — a hostile intermediate cannot extend apparent freshness.

## Migration Story

For most consumers (`rd`, `dontguess`, `social`), the migration is a single
`go.mod` bump. The `pkg/protocol` and `pkg/convention` import paths are
unchanged — they are forwarding shims.

The [upgrade guide](upgrade-0.19-to-0.30.md) covers 18 breaking changes in
detail, with before/after code snippets, rationale, and a decision tree. The
quick summary:

| If your consumer uses... | Required action |
|--------------------------|----------------|
| `WithWalkUp()` / `WithNoWalkUp()` | Remove the call; `Init()` no longer walks up |
| `JoinSession()` / `cfs1_` tokens | Migrate to `cf-session` lazy-mint (BC-4, BC-13) |
| `--transport github` | Migrate to filesystem or HTTP transport (BC-3) |
| `present_as` in config | Remove; use `cf-identity` ceremony instead (BC-6) |
| `pkg/tagspec` or `pkg/reserved_ops` | Switch to `cf-protocol/protocol` re-exports (BC-7) |
| Convention tags with `campfire:` prefix | Rename to convention-specific prefix (BC-8) |
| Direct substrate imports (`pkg/campfire`, etc.) | Switch to `cf-protocol/protocol` (BC-1) |

Five portfolio consumers (`rd`, `dontguess`, `social`, `the reach`, `freeso`)
remain on their current versions until their port windows open. Port windows are
tracked as `campfire-` items in rd.
